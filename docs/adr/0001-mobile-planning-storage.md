# Native Planning UI and transactional local drafts

For implementation ticket #11, choose Expo SDK 55 / React Native with TypeScript and app-private SQLite (`expo-sqlite`), targeting portrait iPhone (iOS 15.1+) and Android phone (API 24+) use. Unlike a browser-only prototype, a bundled native release starts offline and owns durable local storage; compared with separate Swift/Kotlin implementations, the shared TypeScript game-management module gives both platforms one implementation and one primary test seam. These are new engineering choices; the product specification did not select a framework or platform matrix.

Persist each game as a raw draft document in a versioned SQLite database, with transactional read/modify/write operations, WAL, and full synchronization. This retains incomplete and malformed input without coercion while giving each accepted host operation one durable write; an ORM or event log would add machinery with no current query/audit requirement. Newer unknown database versions fail opening rather than replacing saved data; future changes need explicit migrations.

Vitest tests the public application interface using isolated real file-backed Node SQLite stores. Jest/React Native Testing Library supplies a small native-control wiring smoke test using the same module and real stores. Native-device smoke checks remain necessary because the Node adapter does not exercise Expo's native bridge. Synchronous writes are deliberately limited to these small Planning documents; future allocation/settlement work must measure device responsiveness rather than assume expensive calculations can run on the UI thread.
