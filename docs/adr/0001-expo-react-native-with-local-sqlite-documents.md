# Expo / React Native app with local SQLite game documents

The MVP is built with Expo SDK 58 (React Native 0.88, React 19, TypeScript in strict mode) and Expo Router. Android phones in portrait are the first target; iOS uses the same code and is checked later. The product specification deliberately did not select a framework, so this is an engineering choice: one shared TypeScript game-management module serves both platforms and is also the primary test seam, which separate Kotlin/Swift apps would not give us.

All game logic lives behind one public application-level interface, `src/game-management`, which the screens and the integration tests both use. Each game is persisted as one JSON document, with reusable players, chip set templates and the app's working location as further documents, in an app-private SQLite database (`expo-sqlite`). Every accepted host operation computes the new documents in memory and commits them in a single transaction, so a rejected or declined operation cannot leave a partly changed game. Raw, possibly invalid Planning input is stored as text and never coerced. An ORM or event log was not chosen because nothing in the MVP needs relational queries or an audit trail.

Tests run on Jest (`jest-expo`). Integration tests drive the public interface against a real file-backed document store in a temporary directory and recreate the application on the same store to check restart behaviour. Screen tests use React Native Testing Library. The native SQLite adapter itself is only exercised on a device or emulator, so a short device smoke pass stays part of finishing a ticket.
